# Unified Kernel Images, systemd-stub, and TPM2 PCR Policies

## Overview

* **Link in the Chain:** Bridges pre-OS UEFI/shim signature verification ([Chapter 1](01-uefi-shim-sbat.md)) to early userspace (`initrd`) and unattended `LUKS2` disk decryption ([Chapter 3](03-luks2-verity.md)), sealing the classic unsigned-`initramfs` and mutable-command-line gap.
* **Core Security Invariant:** Firmware and `shim` authenticate a single Portable Executable (`UKI`) encompassing `systemd-stub`, `vmlinuz`, `.initrd`, and `.cmdline`, while `systemd-stub` and `systemd-pcrphase` extend cryptographic digests and boot-phase barriers into `TPM 2.0` `PCR[11]` so sealed disk secrets unseal exclusively to vendor-signed images inside the `enter-initrd` window and under `systemd-pcrlock`-authorized platform measurements.
* **Deployment Profile Matrix:** Traditional mutable distros still default to host-generated unsigned `/boot/initramfs-*.img` CPIO archives (with optional `UKI` opt-in on Fedora/RHEL 9.4+/Ubuntu 24.04+); immutable OSes (`Talos`, `Flatcar`, `UKI`-profile `CoreOS`) ship vendor-signed UKIs exclusively; Confidential VMs (`SEV-SNP` / `TDX` in [Chapter 18](18-confidential-vms-svsm.md)) measure UKIs into hardware launch digests or `COCONUT-SVSM` `vTPM` `PCR[11]`.
* **Trusted Computing Base (TCB):** UEFI firmware and `TPM 2.0` (discrete chip, firmware `fTPM`, or `SVSM` `vTPM`), `systemd-stub`, `ukify` / vendor PCR policy signing keys (`.pcrpkey`), `systemd-pcrlock` NV-index pin and event-log parser, and early `initrd` unlock units (`systemd-cryptsetup`).
* **Integration Seam & Handoff:** Delivers an Authenticode-verified kernel, immutable command line (`roothash=`, `lockdown=integrity`),verified `initrd`, and phase-locked `TPM 2.0` volume key to [Chapter 3](03-luks2-verity.md), leaving block/file Merkle verification and post-pivot runtime execution enforcement to [Chapters 3](03-luks2-verity.md) and [4](04-ima-ipe-keylime.md).

## Problem Statement & Threat Model

For over a decade after mainstream Linux distributions enabled `UEFI Secure Boot`, a glaring architectural hole split early boot directly in half [2]. Even when `UEFI`, `shim.efi`, and `GRUB2` verified the compressed kernel image (`/boot/vmlinuz-*`) cleanly, `GRUB2` next loaded two completely unauthenticated artifacts from the unencrypted `/boot` or `ESP` partition: the kernel command line (`cmdline` inside `grub.cfg`) and the initial RAM filesystem (`initramfs-*.img`) [2, 8]. Why did distributions leave `initramfs` unsigned? Because tools such as `dracut`, `mkinitramfs`, and `mkinitcpio` assembled `initramfs` *locally on every end-user machine* during `apt` or `dnf` kernel post-install hooks, baking host-specific `/etc/crypttab`, `/etc/mdadm.conf`, storage drivers, and microcode into a bespoke CPIO archive that the upstream distribution's offline HSM could obviously never sign [2].

Under an offline physical attacker ("Evil Maid") or a transient boot-partition tamper model, that unauthenticated `initramfs` destroys both verified boot and full-disk encryption simultaneously [2, 18]. Inside Linux's boot sequence, the kernel unpacks `initramfs` into an initial `rootfs` in RAM and executes `/init` as `UID 0` *before* unlocking the encrypted `LUKS2` root volume. An attacker who steals or accesses a powered-off laptop in a hotel room for sixty seconds mounts the unencrypted `/boot` partition, unpacks `initramfs`, inserts a five-line keylogger hook into `systemd-ask-password` or `cryptsetup` (exfiltrating the user's passphrase or decrypted volume master key on the subsequent boot), repacks the CPIO archive, and powers the laptop off. On reboot, UEFI reports `SecureBoot = 1`, `shim` and `GRUB2` verify `vmlinuz`, and the trojanized `initramfs` runs with full Ring 3 root authority while the kernel command line remains equally exposed to injected parameters such as `init=/bin/sh` or `systemd.debug_shell=1` [2, 28].

Attempts to paper over that seam by sealing `LUKS2` decryption keys directly to static `TPM 2.0` PCR hashes (`PCR[0,2,4,7,9]`) via legacy scripts (`clevis` raw PCR pins or manual `tpm2_createpolicy`) created two opposite failures [29, 117, 145]. First, if `PCR[9]` (`initrd` measurement) or `PCR[4]` (bootloader/kernel digest) was omitted so routine `apt upgrade` kernel updates would not lock the machine out of its disk, then an Evil Maid attacker could swap in an older signed Ubuntu LiveCD kernel + arbitrary `initramfs`, satisfy `PCR[7]` (same Secure Boot CA!), unseal the `LUKS2` key automatically into RAM, and read the entire disk without knowing any passphrase [2, 146]. Second, if `PCR[4]` and `PCR[9]` *were* pinned statically, every routine security update to `vmlinuz`, `shim`, or `fwupd` UEFI firmware invalidated the static PCR digest and threw headless servers or remote laptops into emergency recovery prompts. Closing the early-boot chasm required unifying the kernel, `initrd`, and command line into a single vendor-signable binary *and* replacing static PCR hash pinning with signed `TPM 2.0` authorization policies plus phase barriers so unsealed keys vanish from TPM reachability before untrusted userspace ever starts [8, 28, 29, 117].

## Kernel & Userspace Mechanics

### Unified Kernel Images (`UKI`) and `systemd-stub`

Standardized by the UAPI Group (`UAPI.5` Type #2 Boot Loader Specification entries [8]) and assembled via `ukify(1)` [147], a `Unified Kernel Image` (`UKI`) eliminates split `/boot` artifacts by linking a compact UEFI boot stub (`systemd-stub`, `linuxx64.efi.stub` on `x86_64` or `linuxaa64.efi.stub` on `ARM64`, initialized with PE `Subsystem = IMAGE_SUBSYSTEM_EFI_APPLICATION` `0x0A` [8, 28]) together with the kernel, early microcode, universal `initrd`, kernel command line, OS release metadata, `.sbat` revocation records, and `TPM 2.0` policy keys into a single `PE/COFF` executable stored in `/EFI/Linux/<id>.efi` on the EFI System Partition:

![Figure: Internal PE/COFF section layout of an Authenticode-signed Unified Kernel Image (UKI) and how systemd-stub extends section digests and monotonic boot-phase barriers into TPM 2.0 PCR[11].](diagrams/02-uki-pe-sections-pcr11.svg)

Under the UAPI `UKI` specification [8], payload PE sections appear after the stub's own `.text`, `.rodata`, `.data`, and `.reloc` sections in a fixed canonical order so `PCR[11]` measurements remain deterministic across toolchains: `.linux` holds the compressed `vmlinuz` kernel image (the sole mandatory payload section); `.osrel` embeds `/etc/os-release` identity fields presented in boot menus; `.cmdline` stores the immutable kernel command line (`roothash=... lockdown=integrity rd.shell=0 rd.emergency=reboot`); `.initrd` holds the compressed `initramfs` CPIO archive; `.ucode` holds an unpadded CPU microcode CPIO archive prepended *ahead* of `.initrd` so Intel/AMD microcode errata mitigations load at the earliest possible Ring 0 cycle; `.splash` carries an optional BMP boot logo; `.dtb` (or multiple hardware-matched `.dtbauto` sections paired with SMBIOS Computer Hardware IDs in `.hwids` and capsule blobs in `.efifw`) supplies compiled Devicetree blobs on `ARM64` platforms without ACPI; `.uname` records the `uname -r` kernel release string; `.sbat` embeds CSV revocation generations ([Chapter 1](01-uefi-shim-sbat.md)); `.pcrsig` embeds a JSON array of pre-signed `PCR[11]` policy signatures; and `.pcrpkey` embeds the PEM-encoded public key $PK_{\text{pcr}}$ corresponding to `.pcrsig` [8, 147]. Starting in `systemd v257`, a single `UKI` can also carry multiple `@profile` sections permitting one vendor-signed `.efi` image to expose distinct verified boot profiles (for example normal multi-user boot vs. attested FIPS or factory-reset profiles) without duplicating the 60 MiB `.linux` + `.initrd` payload [28, 147].

Because PE Authenticode covers every PE section header and raw payload in one signature, `UEFI` `LoadImage()` and `shim.efi` verify `.linux`, `.ucode`, `.initrd`, `.cmdline`, `.dtb`, `.sbat`, and `.pcrpkey` atomically before `systemd-stub` executes its first instruction [8, 28]. Whenever `SecureBoot` is enabled in firmware, `systemd-stub` strictly ignores external UEFI `LoadOptions` command-line strings passed by `BDS`, `efibootmgr`, or `GRUB2`, closing the NVRAM parameter-injection vector (`init=/bin/sh`, `rd.break`, `systemd.debug_shell=1`) [28, 148]. Where legitimately signed host-specific flags, extra initrd drivers, or board Devicetrees are needed without re-signing the vendor `UKI`, `systemd-stub` (`v254+`) scans `/EFI/Linux/<id>.efi.extra.d/*.addon.efi` (and global `/loader/addons/*.addon.efi`) for *PE Addons*: standalone UEFI PE binaries lacking a `.linux` section that carry signed `.cmdline`, `.dtb`, `.ucode`, or `.initrd` sections, verifying each addon through `LoadImage()` / `SHIM_LOCK` before appending its parameters and extending its digest into `PCR[12]` [8, 28]. Simultaneously, `systemd-stub` exports the backing ESP's GPT Partition UUID via the Boot Loader Interface volatile UEFI variable `LoaderDevicePartUUID` (`4a67b082-0a4c-41cf-b6c7-440b29bb8c4f`) so userspace discovers root and `/usr` partitions on the *exact physical NVMe drive* from which the `UKI` booted [28, 149].

To hand the concatenated `.ucode` + `.initrd` + addon CPIO buffers to `vmlinuz` cleanly without touching the untrusted FAT32 ESP or relying on legacy x86-only `boot_params` `ramdisk_image` 32-bit pointers, `systemd-stub` registers an in-memory UEFI `EFI_LOAD_FILE2_PROTOCOL` instance attached to the vendor media device path `LINUX_EFI_INITRD_MEDIA_GUID` (`5568e427-68fc-4f3d-ac74-ca555231cc68`) and jumps into the kernel's EFI stub entry (`efi_pe_entry` in `drivers/firmware/efi/libstub/`) [28, 150, 151]. Before calling `ExitBootServices()`, Linux's `efi_load_initrd()` locates `LINUX_EFI_INITRD_MEDIA_GUID`, pulls the verified CPIO stream directly across `LoadFile2()`, and extends its SHA-256 `EV_IPL` measurement into `TPM 2.0` `PCR[9]` alongside the kernel command line [113, 150, 151].

### `PCR[11]` Section Measurements and Phase-Locked Secret Windows

Before jumping into `.linux`, `systemd-stub` performs a deterministic measurement sweep across every present UKI payload section in canonical order, extending both the NUL-terminated section name (`EV_IPL`) and the section's raw payload digest into `TPM 2.0` `PCR[11]` (and recording the userspace companion log for `/run/log/systemd/tpm2-measure.log`) [28, 113, 117]. Crucially, `PCR[11]` does not freeze once the kernel boots! Instead, `systemd-pcrphase-initrd.service`, `systemd-pcrphase-sysinit.service`, and `systemd-pcrphase.service` invoke `/usr/lib/systemd/systemd-pcrextend` to turn `PCR[11]` into an irreversible *cryptographic state-machine clock*, extending six canonical ASCII phase words across the system lifecycle [28, 116, 117]:

$$\begin{aligned}
\text{PCR}[11]_{\text{stub}} &= \operatorname{ExtendChain}\!\left(0^{256},\; (\text{`.linux`}, \text{`.osrel`}, \text{`.cmdline`}, \text{`.initrd`}, \dots, \text{`.pcrpkey`})\right) \\
\text{PCR}[11]_{\text{initrd}} &= \operatorname{SHA-256}\!\left(\text{PCR}[11]_{\text{stub}} \;\parallel\; \operatorname{SHA-256}(\texttt{"enter-initrd"})\right) \\
\text{PCR}[11]_{\text{leave}} &= \operatorname{SHA-256}\!\left(\text{PCR}[11]_{\text{initrd}} \;\parallel\; \operatorname{SHA-256}(\texttt{"leave-initrd"})\right)
\end{aligned}$$

After `"leave-initrd"` fires immediately prior to `systemctl switch-root`, main-system startup extends `"sysinit"` (once local filesystems mount and basic initialization finishes), followed by `"ready"` (after `remote-fs.target` completes, immediately *before* `systemd-user-sessions.service` permits unprivileged user logins!), and during teardown `"shutdown"` (at `shutdown.target` start) and `"final"` (at final service-manager exit) [116]. Alongside `PCR[11]`, `systemd-pcrosseparator.service` extends `"os-separator"` into `PCR[0..7,9,12..14]` to seal pre-boot firmware registers off from runtime spoofing, while `systemd-pcrmachine.service` and `systemd-pcrfs-root.service` measure `/etc/machine-id` and the mounted root/`/var` filesystem UUIDs into `PCR[15]` [113, 116].

![Figure: Monotonic TPM 2.0 PCR[11] boot-phase transitions from systemd-stub through enter-initrd, leave-initrd, sysinit, ready, shutdown, and final, restricting LUKS2 volume key unsealing strictly to the early initrd window.](diagrams/02-extra-pcr11-boot-phases.svg)

Trace what happens when `systemd-cryptenroll` binds the root `LUKS2` volume key specifically to colon-delimited phase path `enter-initrd` ($\text{PCR}[11]_{\text{initrd}}$) [116, 117, 146]! Inside early `initrd`, `PCR[11]` equals $\text{PCR}[11]_{\text{initrd}}$, allowing `systemd-cryptsetup` to unseal the `LUKS2` volume key from the `TPM 2.0`, program the Ring 0 `dm-crypt` key table, and explicitly zero its userspace buffer. Before `initrd` pivots into the persistent OS root filesystem where network daemons, containers, or interactive logins execute, `systemd-pcrphase-initrd.service` stops and extends `"leave-initrd"` into `PCR[11]` [116]. Because `TPM2_PCR_Extend` is cryptographically one-way, *no process in the booted operating system, not even a compromised `UID 0` daemon or Ring 0 exploit after pivot, can ever coax the `TPM 2.0` into re-unsealing the `enter-initrd`-bound `LUKS2` keyslot again until a clean hardware reset* [111, 116, 117]. Meanwhile, daemon credentials managed by `systemd-creds` ([Chapter 12](12-keyrings-systemd-creds.md)) bind to `enter-initrd:leave-initrd:sysinit` so workload secrets and disk master keys inhabit non-overlapping temporal unseal windows [37, 116].

### `TPM2_PolicyPCR` vs. `PolicyOR` vs. `PolicyAuthorize` vs. `systemd-pcrlock`

Understanding modern Linux TPM sealing requires comparing four `TPM 2.0` Enhanced Authorization (`EA`) policy commands defined in TCG Part 3 [111, 152]. First, `TPM2_PolicyPCR` hashes a bitmask of selected PCRs and their exact expected digest directly into the session's `policyDigest`: it is fast and stateless, yet breaks the instant a single byte of firmware or `vmlinuz` updates. Second, `TPM2_PolicyOR` accepts a list of two to eight candidate 32-byte policy digests ($P_1, \dots, P_8$) and succeeds if the session's current `policyDigest` matches any branch (nesting trees of `PolicyOR` commands supports $8^2 = 64$ or $8^3 = 512$ approved states), yet a static `LUKS2` header still cannot predict hashes of future kernels not yet compiled [29, 152]. Third, `TPM2_PolicyAuthorize` replaces static hash lists with asymmetric delegation: at `ukify build` time, `systemd-measure sign` pre-calculates $\text{PCR}[11]$ for each target boot phase (`enter-initrd`, `enter-initrd:leave-initrd:sysinit`, `enter-initrd:leave-initrd:sysinit:ready`), constructs the trial `TPM2_PolicyPCR` digest $P_{\text{phase}}$, and signs $P_{\text{phase}}$ using the vendor's RSA-2048 or ECDSA P-256 private key $SK_{\text{pcr}}$ [117, 147, 152]. The public key $PK_{\text{pcr}}$ ships in `.pcrpkey` and the per-phase JSON signatures ship in `.pcrsig` [8, 117]. When `systemd-cryptenroll --tpm2-device=auto --tpm2-public-key-pcrs=11` runs, the `LUKS2` token seals against $\operatorname{Name}(PK_{\text{pcr}})$; every future `UKI` signed by $SK_{\text{pcr}}$ carries a fresh `.pcrsig` that `TPM2_VerifySignature` converts into a `TPMT_TK_VERIFIED` ticket satisfying `TPM2_PolicyAuthorize` automatically across upgrades [117, 146, 152]!

![Figure: Combining vendor-signed PCR[11] policies (.pcrpkey/.pcrsig via TPM2_PolicyAuthorize) with local systemd-pcrlock NV-pinned PolicyOR event-log predictions to prevent both Evil-Maid downgrades and upgrade lockouts.](diagrams/02-pcrlock-signed-policy.svg)

Yet relying on vendor-signed `PCR[11]` *alone* leaves a subtle cross-machine and downgrade vulnerability: if a distribution signs one generic `UKI` booted by millions of hosts, an attacker who steals Victim Laptop A's NVMe drive can insert it into Attacker Laptop B, boot that *same valid vendor-signed `UKI`* with Secure Boot disabled or custom UEFI settings, and satisfy `PCR[11]` unless the `LUKS2` policy *also* binds local machine firmware, Secure Boot state, and anti-rollback generation (`PCR[0..7]`) [29, 146]! Introduced in `systemd v255` and requiring `TPM 2.0` revision `1.38+` (`TPM2_PolicyAuthorizeNV`), `systemd-pcrlock(8)` solves host-specific `PCR[0..7,9,14,15]` binding without brittle lockouts [29, 152, 153]. Instead of reading opaque final PCR register hashes, `systemd-pcrlock` parses the binary UEFI TCG event log (`/sys/kernel/security/tpm0/binary_bios_measurements`) and userspace `/run/log/systemd/tpm2-measure.log` into TCG Canonical Event Log (`CEL-JSON` [154]) records, verifying first that replaying the event log reproduces live hardware PCR banks bit-for-bit [29, 153]. It then matches every event against ordered component files (`*.pcrlock` and multi-variant directories `*.pcrlock.d/*.pcrlock` under `/var/lib/pcrlock.d/` and `/usr/lib/pcrlock.d/`): `240-secureboot-policy.pcrlock` (`PCR[7]` `PK`/`KEK`/`db`/`dbx`), `250-firmware-code-early.pcrlock` (`PCR[0,2]`), `400-secureboot-separator.pcrlock`, `600-gpt.pcrlock` (`PCR[5]` GPT header), `620-secureboot-authority.pcrlock` (`PCR[7]` exact X.509 signer), `700-action-efi-exit-boot-services.pcrlock`, and `750-enter-initrd.pcrlock` [153].

Whenever two kernels or a staged `fwupd` capsule coexist on disk, `pcrlock` evaluates the Cartesian product of all authorized component variants, folds the resulting PCR combinations into balanced 8-way `TPM2_PolicyOR` trees, and writes the authorized root policy digest into a local `TPM 2.0` Non-Volatile (`NV`) index gated by an encrypted access PIN (and optional `--recovery-pin=`) [29, 152]. Because `/var/lib/systemd/pcrlock.json` sits inside the still-locked root disk at early boot, `systemd-pcrlock make-policy` (`v256+`) also writes an unencrypted metadata credential copy to `/loader/credentials/pcrlock.<token>.cred` on the ESP, which `systemd-stub` passes into `initrd` so `systemd-cryptsetup` can reconstruct the winning `PolicyOR` branch and satisfy `TPM2_PolicyAuthorizeNV` against the hardware NV index [28, 29]! Old revoked UKIs or foreign motherboards fail the NV-pinned `PolicyOR` evaluation immediately, while legitimate updates advance the NV index atomically without re-encrypting `LUKS2` keyslots.

### `systemd-cryptenroll`, `Clevis`/`Tang`, and `CONFIG_TCG_TPM2_HMAC` Bus Encryption

Historically, enterprise Linux servers automated unattended disk unlocking via `Clevis` (`clevis-luks-bind`), pairing either Network-Bound Disk Encryption (`Tang` [145, 155], which executes an asymmetric McCallum-Relyea elliptic-curve key exchange where an on-premises `Tang` daemon multiplies a client-blinded point by its server private key so the client recovers its `LUKS2` key only on the corporate LAN without `Tang` ever seeing the client secret) or a `tpm2` JWE pin [145]. While `Tang` remains useful on legacy TPM-less rack servers, `Clevis`'s `tpm2` pin binds raw static `TPM2_PolicyPCR` hashes (`-p '{"pcr_ids":"7"}'`), leaving administrators trapped between `PCR[7]`-only Live-ISO bypasses and kernel-upgrade lockouts [145, 146, 156]. Modern Linux standardizes on `systemd-cryptenroll(1)` [146], combining signed `PCR[11]` + `systemd-pcrlock` policies with optional pre-boot `TPM2` PINs (`--tpm2-with-pin=yes`, rate-limited by hardware `TPM 2.0` Dictionary Attack lockout counters) or `FIDO2` `hmac-secret` hardware security keys (`--fido2-device=auto`) stored in native `LUKS2` JSON tokens [18, 146].

One physical hardware seam still remained on laptops and servers equipped with discrete `TPM 2.0` chips soldered onto a motherboard `SPI`, `LPC`, or `eSPI` bus [156, 157, 158]: passive bus interposers (`TPM Genie` [158] or a $50 logic analyzer clipped onto the 8-pin SOIC package [156]) could watch `TPM2_Unseal` return the 32-byte plaintext `LUKS2` volume key in cleartext across motherboard traces, or spoof `TPM2_PCR_Extend` packets in flight! Merged in Linux `6.10` (`CONFIG_TCG_TPM2_HMAC=y`, `Documentation/security/tpm/tpm-security.rst` by James Bottomley [157, 159]) and supported by `systemd`'s TPM2 stack, Linux closes passive and active bus sniffing by deriving an ephemeral elliptic-curve primary key from the TPM's `TPM_RH_NULL` hierarchy seed at early boot (`null_key`, whose seed changes across every TPM reset, defeating bus-reset measurement replay!). Every kernel and `systemd` TPM transaction establishes a session salted asymmetrically against `null_key`: `TPM2_PCR_Extend` commands carry salted `HMAC` integrity tags (detecting active interposer packet tampering), `TPM2_Unseal` responses enable `CFB` `parameter encryption` (`TPMA_SESSION_ENCRYPT`) so the `LUKS2` key crosses the physical `SPI` bus strictly encrypted, and `/sys/class/tpm/tpm0/null_name` exports the null-primary's cryptographic `Name` so post-boot attestation (`TPM2_Certify` via `AK`/`EK` in [Chapter 4](04-ima-ipe-keylime.md)) proves no active MITM substituted the initial `TPM2_CreatePrimary` public key at boot [157, 159].

## Distro, Immutable-OS, & Cloud Trade-Offs

Transitioning from locally assembled `/boot/initramfs-*.img` archives to vendor-signed `UKI` binaries forces distributions to solve two deep systems-engineering problems: building a *universal* ("host-independent") `initrd` and provisioning enough FAT32 EFI System Partition capacity [2, 8, 160]. Historically, `dracut --hostonly` kept `initramfs` down to ~25 MiB by inspecting the running host's `sysfs` PCIe/NVMe topology and `/etc/crypttab` at package-install time. A vendor-signed `UKI`, by contrast, must boot identically across laptops, RAID workstations, NVMe servers, and cloud VMs without per-machine rebuilds: it bundles generic storage, HID keyboard, `TPM 2.0` (`tpm_tis`, `tpm_crb`), `dm-crypt`, `dm-integrity`, and `dm-verity` drivers inside one universal `initrd` (~60 to 115 MiB per `.efi` image) and discovers `/`, `/usr`, `/var`, and swap dynamically at boot via UAPI Discoverable Partitions GPT type UUIDs rather than baked-in `/etc/fstab` files [2, 8, 149, 160]. Because legacy Windows dual-boot laptops frequently shipped tiny `100` to `260 MiB` EFI System Partitions incapable of holding three parallel `100 MiB` UKI generations plus firmware capsules, modern installers (`Fedora`, `Arch`, `systemd-boot` layouts) either allocate a `1` to `2 GiB` ESP up front or pair the small ESP with an unencrypted GPT Extended Boot Loader Partition (`XBOOTLDR`, GPT Type UUID `bc13c2ff-59e6-4262-a352-b275fd6f7172`) read natively by `systemd-boot` [147, 160].

Across deployment profiles, three distinct `UKI` signing models have emerged [8, 45, 46, 147]. Immutable operating systems (`Talos Linux`, `Flatcar`, `Bottlerocket`, `Ubuntu Core` `linux-image-uc`) ship exclusively vendor-HSM-signed `UKI` artifacts paired with `.pcrpkey`/`.pcrsig` `PCR[11]` signatures; hosts never run compilers, `dracut`, or signing keys locally [45, 46]. Mainstream enterprise and workstation distributions (`Fedora 40+` Cloud/Atomic, `RHEL 9.4+` / `10` `kernel-uki-virt`, `Debian` / `Arch Linux` `ukify` + `sbctl`) support both vendor-built cloud UKIs and *locally assembled UKIs* for bare-metal hosts requiring custom out-of-tree drivers or bespoke kernel flags: on local builds, `kernel-install` invokes `ukify build` during package upgrades, signs the resulting PE image with a host-specific custom `db` or `MOK` key (`sbctl`) plus a local `/etc/kernel/pcr-initrd.key.pem` `PCR[11]` key, and refreshes `systemd-pcrlock make-policy` automatically [29, 147]. Notice the threat-model trade-off: a vendor-signed `UKI` protects kernel and `initrd` integrity even against a transient `UID 0` attacker on the host (since the private signing keys live in the distro's offline HSM), whereas a locally signed `UKI` stops offline Evil Maid tampering on `/boot` while trusting runtime `UID 0` if the local signing key sits unsealed on disk!

In public-cloud Virtual Machines (`AWS Nitro` UEFI, `Azure Trusted Launch`, `GCP Shielded VM`), virtual `TPM 2.0` NVRAM and PCR banks reside inside hypervisor-managed host state: `UKI` + `PCR[11]` + `systemd-pcrlock` cleanly blocks guest bootkits and offline EBS/PD disk-snapshot tampering by external tenants, while leaving the cloud operator inside the `TCB`. Removing the cloud hypervisor itself from the `UKI` and `vTPM` trust boundary requires Confidential VMs ([Chapter 18](18-confidential-vms-svsm.md)), where `OVMF` or `COCONUT-SVSM` running in `AMD SEV-SNP` `VMPL0` (or `Intel TDX` `TDVF` extending `RTMR[1..2]`) measures the `UKI` directly into hardware-attested silicon launch registers before unsealing secrets [3, 4, 11].

## Seam Failures, CVEs, & Structural Bounds

Even with `TPM 2.0` sealing and `UKI` packaging, real-world bypasses cluster around omitting `initrd`/phase PCRs, discrete `SPI`/`LPC` bus sniffing, firmware `fTPM` silicon fault injection, and unauthenticated rescue shells inside `initrd`.

| Incident / CVE | Year | Subsystem | Broken Assumption | Exploit Mechanism | Architectural Fix |
|---|---|---|---|---|---|
| Unauthenticated `initramfs` Evil Maid | 2012-2024 | Classic `GRUB2` + `/boot` CPIO | `UEFI Secure Boot` verifies the entire pre-LUKS boot chain | Offline attacker injects passphrase logger into unsigned `/boot/initramfs-*.img` | Replace split `vmlinuz`+`initrd` with Authenticode-signed `UKI` [2, 8] |
| `initrd` Rescue Shell Breakout (`CVE-2016-4484`) | 2016-2023 | `cryptsetup` / `dracut` error handlers | Failed root unlock safely halts boot | Holding Enter ~70 times on passphrase fail drops attacker into unauthenticated `UID 0` `initrd` shell inside `enter-initrd` | Bake `rd.shell=0 rd.emergency=reboot` into signed `UKI` `.cmdline` [8, 148, 161] |
| Discrete `TPM 2.0` Bus Sniffing (`TPM Genie`) | 2018-2024 | Unencrypted motherboard `SPI`/`LPC`/`eSPI` bus | `TPM2_Unseal` travels privately between discrete TPM and CPU | Passive $50 logic analyzer or interposer captures plaintext `LUKS2` key or spoofs `PCR_Extend` packets | Enable null-seed salted `CONFIG_TCG_TPM2_HMAC` parameter encryption (Linux `6.10+`) and `--tpm2-with-pin=yes` [146, 156, 157, 158, 159] |
| `TPM-Fail` Timing Side Channel (`CVE-2019-16863`, `CVE-2019-11090`) | 2019-2020 | Intel `fTPM` & STMicroelectronics `TPM 2.0` | Hardware-isolated ECDSA signing runs in constant time | Nonce bit-length timing leaks let lattice reduction recover 256-bit `TPM` ECDSA keys in ~1,300 signatures | Flash vendor `TPM 2.0` / BIOS constant-time ECDSA firmware updates [162] |
| `PCR[7]`-Only Live-ISO & Soft-Reboot Bypass (`CVE-2023-21563` class) | 2021-2024 | `Clevis` / naive `PCR[7]`-only policies | `PCR[7]` alone proves the host OS and `initrd` are authentic | Attacker boots signed distro Live USB or PXE recovery under same `db` CA (`PCR[7]` identical) and unseals or scrapes DRAM | Bind signed `PCR[11]` (`enter-initrd`) + `systemd-pcrlock` (`PCR[0,4,5,7,9]`) + `PCR[15]` [29, 117, 156, 163] |
| `TPM 2.0` Reference Code OOB (`CVE-2023-1017`, `CVE-2023-1018`) | 2023 | TCG `TPM 2.0` `ExecuteCommand` parameter parser | Encrypted parameter size headers in `CryptParameterDecryption` are bounded | Crafted cipher-size fields trigger 2-byte OOB write/read inside `fTPM`, `vTPM`, or discrete `TPM` RAM | Update host UEFI `fTPM`, hypervisor `libtpms` (`swtpm`), and discrete TPM firmware [164] |
| `faulTPM` Voltage Glitching (`CVE-2023-20592`) | 2023 | AMD Zen 2 / Zen 3 `ASP` firmware `fTPM` | CPU-integrated `fTPM` defeats physical `SPI` bus probing completely | Hours-long physical voltage fault injection against `ASP` SPI flash checks dumps full internal `fTPM` seed and skips PIN lockouts | Apply AMD AGESA microcode patches and combine `TPM2` PIN with `Argon2id` passphrase on high-risk travel laptops [146, 165] |
| Vendor-Signed `UKI` Downgrade | 2023-2024 | `TPM2_PolicyAuthorize` without local NV counter | Old `SK_pcr`-signed `UKI` binaries lose unseal rights after patching | Attacker swaps vulnerable older vendor-signed `UKI` + `.pcrsig` onto ESP and satisfies `PK_pcr` | Combine `.pcrsig` with `SBAT` bumps and `systemd-pcrlock` `TPM2_PolicyAuthorizeNV` local generation pin [7, 29, 152] |

> **Warning.**
> Kernel and `systemd` `TPM 2.0` parameter encryption (`CONFIG_TCG_TPM2_HMAC` [157, 159]) encrypts the unsealed secret in transit across the physical `SPI`/`LPC` bus between a discrete TPM and host DRAM, defeating passive `TPM Genie` logic-analyzer sniffing [156, 158]. However, unattended TPM-only unlocking (`--tpm2-with-pin=no`) still deposits the decrypted `LUKS2` master key into host DRAM automatically at power-on, remaining exposed to physical DRAM cold-boot extraction, pre-IOMMU `PCIe` DMA, or multi-hour silicon fault injection (`faulTPM` `CVE-2023-20592` [165]) unless gated by an interactive pre-boot `--tpm2-with-pin=yes` secret or `--fido2-device` token [146].

## Inspecting on a Live Linux Host

Inspect the PE/COFF sections of an installed Unified Kernel Image (`.linux`, `.ucode`, `.initrd`, `.cmdline`, `.sbat`, `.pcrsig`, `.pcrpkey`) and review `PCR` values:

```bash
ukify inspect /boot/efi/EFI/Linux/*.efi 2>/dev/null || objdump -h /boot/efi/EFI/Linux/*.efi 2>/dev/null
systemd-analyze pcrs 0 4 7 9 11 12 14 15
```

Examine the TCG Canonical Event Log (`CEL`) components parsed by `systemd-pcrlock`, check `PolicyAuthorizeNV` hardware support, and verify Linux `6.10+` `TPM` null-primary bus protection:

```bash
/usr/lib/systemd/systemd-pcrlock is-supported 2>/dev/null || true
/usr/lib/systemd/systemd-pcrlock list-components 2>/dev/null | head -n 16
cat /sys/class/tpm/tpm0/null_name 2>/dev/null || true
```

Verify which keyslots and `TPM 2.0` / `FIDO2` tokens (`systemd-tpm2`, `pcrlock`, `pcr11`) are enrolled inside a `LUKS2` block device header without touching volume keys:

```bash
# Replace /dev/nvme0n1p3 with your LUKS2 partition from lsblk -f
cryptsetup luksDump /dev/nvme0n1p3 2>/dev/null | head -n 40
```

Pre-calculate expected `PCR[11]` phase digests for a `UKI` binary using `systemd-measure`:

```bash
/usr/lib/systemd/systemd-measure calculate --linux=/boot/vmlinuz-$(uname -r) 2>/dev/null | head -n 12
```
