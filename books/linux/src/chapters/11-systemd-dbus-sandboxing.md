# Service Sandboxing and D-Bus IPC Mediation

## Overview

* **Link in the Chain:** Confines long-running system daemons (`systemd.exec` units) and mediates inter-process privilege requests (`D-Bus`, `Polkit`, `Varlink`) immediately above capability and SUID-replacement primitives ([Chapters 9](09-capabilities-userns.md) and [10](10-suid-to-run0.md)).
* **Core Security Invariant:** Every background daemon executes inside a bespoke per-unit namespace, capability, and `seccomp-BPF` sandbox (`DynamicUser=yes`, `ProtectSystem=strict`, `SystemCallFilter=@system-service`), while every privileged IPC broker authenticates peers using immutable kernel-captured socket credentials (`SO_PEERCRED`) and race-free process file descriptors (`SO_PEERPIDFD` and `SCM_PIDFD`) rather than recyclable numeric `PID`s.
* **Deployment Profile Matrix:** Modern mutable distributions (`Fedora`, `Ubuntu`, `Debian`, `RHEL`) ship progressively hardened upstream `systemd` unit files paired with `dbus-broker` (`Fedora`, `Arch`, `RHEL 9/10`) or `dbus-daemon` (`Ubuntu`, `Debian`); immutable appliances (`Fedora CoreOS`, `Flatcar`) lock `/usr` read-only across units; `Talos Linux` omits `systemd` and `D-Bus` completely in favor of a minimal `machined` `PID 1` speaking mTLS gRPC.
* **Trusted Computing Base (TCB):** `systemd` (`PID 1` unit spawner, `src/core/namespace.c` mount-namespace builder, and `libseccomp` filter compiler), `dbus-broker` or `dbus-daemon` bus policy engines, `polkitd` (`polkit(8)` authority), `sd-varlink` UNIX socket listeners, and Linux `AF_UNIX` `SO_PEERCRED` and `pidfd` kernel primitives.
* **Integration Seam & Handoff:** Contains remote or local code execution inside network and hardware daemons so a compromised `nginx`, `bluetoothd`, or `cups-browsed` cannot pivot to host files or kernel exploits, and secures local RPC calls; delegates cryptographic secret injection (`LoadCredentialEncrypted=`) to [Chapter 12](12-keyrings-systemd-creds.md).

## Problem Statement & Threat Model

When `run0` ([Chapter 10](10-suid-to-run0.md)), `NetworkManager`, `fwupd`, `systemd-resolved`, `bluetoothd`, or `cupsd` operate on a modern Linux host, two distinct attack surfaces replace legacy monolithic root scripts [68, 340, 341]. First, dozens of C and C++ background daemons continuously parse untrusted network frames and peripheral inputs: `DNS` and `mDNS` records, `DHCPv6` options, `IPP` printer attributes, `Bluetooth` L2CAP packets, `USB` descriptors, and `HTTP` payloads. Under classic SysV init scripts (`/etc/init.d/*`), every daemon that bound a port below `1024`, opened a `/dev` node, or persisted state under `/var/lib/<service>` started as unconstrained `UID 0` sharing the host's writable `/tmp`, `/var/tmp`, `/dev`, `/proc`, `/home`, and 350+ system calls [68, 342]. A single parser flaw handed an adversary `/etc` reads, `/proc` command-line visibility, `/var/tmp` staging, and `CLONE_NEWUSER` or `io_uring` kernel exploit surfaces ([Chapters 6](06-kernel-memory-rust.md) and [9](09-capabilities-userns.md)). In September 2024, Simone Margaritelli's `CUPS` disclosure (`CVE-2024-47176` chain [343]) demonstrated that exact risk: a single UDP packet to port `631` caused `cups-browsed` to connect back to an attacker IPP server, ingest malicious `PPD` directives, and execute arbitrary shell commands via `FoomaticRIPCommandLine`.

Second, decomposing root privileges into cooperating daemons (`systemd-machined`, `systemd-logind`, `AccountsService`, `PackageKit`, `udisks2`, `tuned`) over Desktop Bus (`D-Bus` [340]) or `Varlink` [70, 344] sockets introduces a local Confused Deputy IPC surface. Unprivileged local users (`UID 1000` or a compromised daemon) open `/run/dbus/system_bus_socket` and invoke RPC methods on root services. How does the receiving daemon and `polkitd` [333] prove *which* kernel task sent an IPC request without racing process exit, `execve()`, or PID wraparound? For over a decade, D-Bus services passed an ephemeral bus unique name (`:1.92`) or a 32-bit numeric `pid_t` (`kernel.pid_max` `32768` or `4194304`) across asynchronous IPC hops and inspected `/proc/<pid>/status` in userspace [341, 345, 346]. Because processes can terminate via `SIGKILL` or transition credentials via `execve()` in microseconds, lazy `/proc/<pid>` resolution and sloppy disconnect handling produce catastrophic Time-of-Check to Time-of-Use (`TOCTOU`) privilege escalations (`CVE-2013-4288` [345], `CVE-2021-3560` [341]). Meanwhile, because `PID 1` and the message bus sit in the critical path of every mount and log event, unbounded stack allocations inside those brokers (`CVE-2021-33910` [347], `CVE-2018-16864` [348]) can panic the entire kernel. Hardening Linux userspace therefore requires pairing *declarative per-service confinement* with *race-free kernel-handle IPC authentication*.

## Kernel & Userspace Mechanics

### Mount Namespace Assembly in `PID 1`: `ProtectSystem=`, `PrivateDevices=`, and `CVE-2021-33910`

Rather than forcing administrators to wrap every system daemon inside a full OCI container or hand-author custom `SELinux` policies from scratch, `systemd` (`src/core/execute.c` and `src/core/namespace.c` [68, 349]) compiles over sixty orthogonal Linux kernel isolation primitives directly from declarative `[Service]` directives *between `clone()` and `execve()`* inside the unit executor helper (`sd-executor`):

![Figure: Four concentric layers of systemd.exec(5) daemon sandboxing: ephemeral DynamicUser=yes identity, per-service VFS mount namespaces (ProtectSystem=strict), kernel tunable/module/namespace locks, and seccomp-BPF SystemCallFilter allowlists.](diagrams/11-systemd-unit-sandbox-layers.svg)

Follow the exact VFS mount-table construction inside `setup_namespace()` (`src/core/namespace.c` [68, 349]) when `PID 1` spawns a confined service. First, the child executor calls `unshare(CLONE_NEWNS)` to sever its mount descriptor table from the host's root mount namespace, immediately marking all inherited mounts recursively `MS_SLAVE` (`mount(NULL, "/", NULL, MS_SLAVE | MS_REC, NULL)`). Slave propagation enforces a subtle one-way directional valve: when a host administrator mounts an emergency security volume or rotates a host mount at runtime, mount events propagate *inward* from the host master mount peer group into running service namespaces, whereas any mount, remount, or unmount executed inside the unit's namespace can never propagate *outward* to contaminate the host or sibling services [68, 349]. Next, `systemd` compiles all configured sandboxing directives into a flat array of `MountEntry` records, sorts them lexicographically by normalized destination path so parent mounts precede nested exceptions, resolves targets safely against symlink redirection, and applies bind mounts, `tmpfs` overlays, and `MS_RDONLY` remounts in order:

| `systemd.exec(5)` Directive | Kernel Primitive Constructed in `src/core/namespace.c` | Concrete Post-RCE Attack Primitive Eliminated |
|---|---|---|
| `ProtectSystem=strict` | Remounts the entire `/` hierarchy `MS_RDONLY` except `/dev`, `/proc`, `/sys`, and declared `StateDirectory=` or `RuntimeDirectory=` paths | Blocks persistent binary trojaning in `/usr`, config tampering in `/etc`, and web-shell drops across `/var` [68, 349] |
| `ProtectHome=yes` | Bind-mounts empty inaccessible (`0000`) `tmpfs` directories over `/home`, `/root`, and `/run/user` (`tmpfs` mode mounts empty read-only RAM roots) | Prevents compromised daemons from harvesting `~/.ssh` keys, browser cookies, or user Wayland and D-Bus sockets [68, 349] |
| `PrivateTmp=yes` | Bind-mounts isolated `/tmp/systemd-private-<bootid>-<unit>-<rand>/tmp` (or unbacked `tmpfs` under `PrivateTmp=disconnected`) over `/tmp` and `/var/tmp` | Eliminates `/tmp` symlink and FIFO races against root cron jobs and purges attacker staging files on unit stop [68] |
| `PrivateDevices=yes` | Mounts minimal `tmpfs` (`MS_NOSUID \| MS_NOEXEC`) at `/dev` exposing only `null`, `zero`, `full`, `random`, `urandom`, `tty` + `BPF_PROG_TYPE_CGROUP_DEVICE` | Blocks raw disk reads (`/dev/nvme0n1`), `/dev/mem` physical memory access, and `mknod` device node creation [68, 349] |
| `ProtectProc=invisible` + `ProcSubset=pid` | Mounts the unit's `/proc` instance with `hidepid=invisible,subset=pid` (`proc(5)` Linux 5.8+) | Hides all non-owned PIDs and strips `/proc/kallsyms`, `/proc/modules`, and `/proc/slabinfo` KASLR leaks [68, 350] |
| `ProtectKernelTunables=yes` + `ProtectControlGroups=yes` | Remounts `/proc/sys`, `/sys`, `/proc/acpi`, `/proc/timer_list`, and `/sys/fs/cgroup` recursively `MS_RDONLY` | Blocks sysctl tampering (`kernel.core_pattern`, `kernel.modprobe`) and cgroup hierarchy escapes [68, 349] |

Contrast the three gradations of `ProtectSystem=` carefully [68]: `ProtectSystem=yes` mounts only `/usr` and `/boot` (or `/efi`) read-only, leaving `/etc` and `/var` writable; `ProtectSystem=full` adds `/etc` to the read-only set while leaving `/var` open; only `ProtectSystem=strict` remounts the entire root tree read-only, requiring explicit opt-in write paths via `StateDirectory=` [68, 349]. Paired with `ProtectKernelModules=yes` (hiding `/usr/lib/modules`, dropping `CAP_SYS_MODULE`, and blocking `finit_module`) and `ProtectClock=yes`, `PID 1` strips a daemon's visible filesystem down to an appliance view.

Because `PID 1` itself continuously observes `/proc/self/mountinfo` to synthesize `.mount` units, `systemd`'s mount parser sits inside the ultimate userspace TCB. In July 2021, while investigating the kernel `seq_file` overflow (`Sequoia`, `CVE-2021-33909` [351]), Qualys uncovered `CVE-2021-33910` [347] in `systemd` (`v220` through `v248`): `mount_setup_unit()` passed every mountpoint path into `unit_name_path_escape()`, where commit `7410616c` duplicated the path onto `PID 1`'s stack via `strdupa()` (`alloca()`). An unprivileged user mounting a FUSE tree deeper than `8 MiB` (`RLIMIT_STACK`) drove `PID 1`'s `%rsp` past the stack guard page, killing `init` with `SIGSEGV` and panicking the kernel, echoing Qualys's `CVE-2018-16864`/`16865` `alloca()` stack clashes in `systemd-journald` [347, 348]. Upstream `systemd` replaced unbounded `strdupa()` calls with heap allocations and enabled `-fstack-clash-protection`.

### Ephemeral Service Identity: `DynamicUser=yes`, `StateDirectory=`, and Symlink Ownership Traps

Traditional `.rpm` and `.deb` pre-install scripts (`useradd -r myapp`) permanently mutate `/etc/passwd`, hinder stateless factory resets ([Chapter 3](03-luks2-verity.md)), and leave static UIDs owning persistent files forever. Setting `DynamicUser=yes` [342, 352, 353] allocates transient UIDs strictly for the lifetime of one service activation. When `my-api.service` starts, `PID 1` hashes the unit name via SipHash-2-4 into `61184..65519` (`0xEF00..0xFFEF` [353]), acquires an advisory lock under `/run/systemd/dynamic-uid/` to avoid active UID or IPC collisions, and resolves `getpwuid()` dynamically over `/run/systemd/userdb/io.systemd.DynamicUser` (`nss-systemd(8)` [352]), releasing the UID on unit stop.

If `DynamicUser=yes` switched UIDs without locking down writable paths, a compromised unit leased `UID 62301` could drop a `04755` setuid binary in `/var/tmp` and hijack whichever future dynamic service collided onto `UID 62301` [342]. Therefore `DynamicUser=yes` *unconditionally implies* five invariants [68, 342]: `NoNewPrivileges=yes`, `RestrictSUIDSGID=yes` (`seccomp-BPF` blocking `chmod`/`fchmodat`/`open`/`mknod` with `S_ISUID | S_ISGID`), `RemoveIPC=yes` (purging SysV and POSIX IPC objects on stop), `PrivateTmp=yes`, and `ProtectSystem=strict` + `ProtectHome=read-only`.

When a `DynamicUser=yes` service declares persistent storage via `StateDirectory=myapp`, `PID 1` creates `/var/lib/private` (`0700 root:root`), allocates `/var/lib/private/myapp` owned by the leased dynamic UID, and symlinks `/var/lib/myapp` to `private/myapp` [342]. Outside the unit's private mount namespace, no non-root process can traverse `0700` `/var/lib/private` even if leased the identical UID later! Early `StateDirectory=` implementations (`CVE-2018-15688` / `15686` era) exposed a sharp restart race: when a restarting unit received a different dynamic UID and `PID 1` recursively `chown`ed `/var/lib/private/myapp` as `UID 0`, a symlink planted inside that directory could trick `PID 1` into `chown`ing `/etc/shadow`! Modern `systemd` (`chase()`) traverses every component using `O_PATH | O_NOFOLLOW` and `openat2(RESOLVE_NO_SYMLINKS)` [103] before calling `fchownat(AT_EMPTY_PATH)`, or uses kernel idmapped mounts (`MOUNT_ATTR_IDMAP`) to project dynamic UID ownership in VFS without touching on-disk `i_uid` metadata [68, 342].

### Syscall, Personality, and `W^X` Gates: `SystemCallFilter=`, `LockPersonality=`, and Exposure Scoring

Even inside a read-only mount namespace under an ephemeral UID, an attacker who achieves arbitrary native code execution inside a C/C++ network daemon immediately turns toward Ring 0 (`bpf`, `io_uring_setup`, `userfaultfd`, `perf_event_open`, `keyctl`, or `nf_tables` netlink sockets) to escalate to host kernel privileges ([Chapters 6](06-kernel-memory-rust.md), [8](08-ebpf-dual-edge.md), and [9](09-capabilities-userns.md)). Four declarative `systemd.exec(5)` directives lock down execution domains, executable heap/stack mappings, socket families, and system call dispatch [68, 354]:

First, `LockPersonality=yes` installs a `seccomp-BPF` filter freezing the Linux execution domain (`personality(2)` [355]) to `PER_LINUX`, blocking both `PER_LINUX32` layout shifts and `READ_IMPLIES_EXEC` (a legacy 32-bit compatibility flag that silently marks every readable VMA page executable!). Second, `MemoryDenyWriteExecute=yes` enforces userspace Write-XOR-Execute (`W^X`) via `seccomp-BPF`, returning `EPERM` on `mmap()`, `mprotect()`, and `pkey_mprotect()` whenever `PROT_WRITE | PROT_EXEC` are requested together (and blocking `shmat()` with `SHM_EXEC`), forcing attackers on non-JIT daemons to rely solely on existing code gadgets [68]. Third, `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6` installs a socket-domain filter denying `socket(2)` creation for `AF_NETLINK` (severing `nf_tables` `CVE-2024-1086`!), `AF_PACKET` (`TPACKET_V3`), `AF_VSOCK`, `AF_BLUETOOTH`, `AF_RDS`, and `AF_TIPC`, while `IPAddressDeny=any` + `IPAddressAllow=10.0.0.0/8` attaches per-cgroup `BPF_PROG_TYPE_CGROUP_SKB` ingress/egress IP filters directly to the unit's `cgroup v2` slice [68]!

Fourth, `SystemCallArchitectures=native` paired with `SystemCallFilter=@system-service` compiles a curated `libseccomp` cBPF program (`src/shared/seccomp-util.c` [354]). As `Documentation/userspace-api/seccomp_filter.rst` emphasizes [104], filtering `x86_64` `__NR_*` syscall numbers *without* `SystemCallArchitectures=native` leaves a gaping hole on kernels compiled with `CONFIG_IA32_EMULATION=y`: a 64-bit process issuing `int $0x80` enters Ring 0 with `seccomp_data.arch == AUDIT_ARCH_I386`, where syscall `38` is `rename` on `i386` rather than `setitimer` on `x86_64`, bypassing naive 64-bit filters completely! Combining `SystemCallArchitectures=native` with `SystemCallFilter=@system-service` and `~@privileged ~@resources` permits standard POSIX file, memory, epoll, and thread operations while denying eleven dangerous kernel syscall groups compiled in `seccomp-util.c` [354]: `@aio` / `io_uring`, `@clock` (`adjtimex`, `clock_adjtime`), `@cpu-emulation` (`modify_ldt`, `vm86`), `@debug` (`ptrace`, `perf_event_open`, `kcmp`, `lookup_dcookie`), `@module` (`init_module`, `finit_module`, `delete_module`), `@mount` (`mount`, `umount2`, `pivot_root`, `fsopen`, `fsmount`, `move_mount`), `@obsolete` (`_sysctl`, `uselib`, `bdflush`), `@privileged` (`chown`, `chroot`, `capset`, `acct`, `bpf`), `@raw-io` (`ioperm`, `iopl`), `@reboot` (`reboot`, `kexec_load`, `kexec_file_load`), and `@swap` (`swapon`, `swapoff`) [68, 354]. Operators should also set `SystemCallErrorNumber=EPERM` alongside `SystemCallFilter=` when hardening third-party daemons whose `glibc` probes might conditionally attempt a blocked syscall and handle `-EPERM` cleanly instead of dying violently under default `SECCOMP_RET_KILL_PROCESS` (`SIGSYS`) [68, 104].

To make these sixty-plus directives measurable across an entire host, `systemd-analyze security [UNIT]` [356] evaluates every active `.service` unit against weighted exposure penalties (`User=/DynamicUser=`, `PrivateNetwork=`, `ProtectSystem=`, `CapabilityBoundingSet=`, `NoNewPrivileges=`, `SystemCallFilter=`, `SystemCallArchitectures=`, `RestrictNamespaces=`, `MemoryDenyWriteExecute=`, `LockPersonality=`, `RestrictSUIDSGID=`, `Delegate=`), computing an aggregate exposure score from `0.0 SAFE` to `10.0 UNSAFE`. Crucially, `systemd-analyze(1)` states the structural bound of unit scoring explicitly [356]: unit sandboxing restricts only what the service process can ask the *kernel* to do directly; if that service retains an open socket to `D-Bus`, any unmediated method call it invokes against a root daemon executes outside the unit's sandbox!

### `D-Bus` (`dbus-daemon` vs. `dbus-broker`), `Polkit` Races (`CVE-2013-4288` & `CVE-2021-3560`), `SO_PEERPIDFD`, and `Varlink`

Local IPC mediation on Linux begins inside `net/unix/af_unix.c` [357]. At the exact instant a client executes `connect(2)` against `/run/dbus/system_bus_socket` or a `Varlink` UNIX domain socket, the kernel captures an immutable snapshot of the client thread's `struct cred` (`uid`, `gid`, supplementary group list, and `SELinux`/`AppArmor` security label) together with a reference-counted pointer to its `struct pid` inside `sock->sk_peer_cred` and `sock->sk_peer_pid` [357, 358]:

```c
/* Kernel-captured peer credentials & unforgeable pidfd (Linux 6.5+ unix(7)) */
struct ucred cred;
socklen_t cred_len = sizeof(cred);
int peer_pidfd = -1;
socklen_t pidfd_len = sizeof(peer_pidfd);

/* Immutable UID/GID/LSM snapshot + race-free struct pid descriptor! */
getsockopt(client_fd, SOL_SOCKET, SO_PEERCRED, &cred, &cred_len);
getsockopt(client_fd, SOL_SOCKET, SO_PEERPIDFD, &peer_pidfd, &pidfd_len);
```

When the message bus queries `SO_PEERCRED`, `SO_PEERGROUPS`, and `SO_PEERSEC` [357], userspace cannot spoof those values or mutate them after `connect()`. Why, then, did classic `D-Bus` and `Polkit` suffer recurring Denial-of-Service and root privilege-escalation failures?

First, compare the legacy reference daemon (`dbus-daemon` [340]) against `dbus-broker` [359], now the default system bus across `Fedora`, `RHEL 9/10`, and `Arch`. Legacy `dbus-daemon` combined XML configuration parsing, NSS lookups, and message routing inside one monolithic process backed by shared global memory and FD pools: a single unprivileged local user opening maximum bus connections, subscribing wildcard `AddMatch` broadcast rules, or stalling reads to back up outgoing queues could exhaust global bus limits and block `PID 1` or `systemd-logind` from communicating [359]. `dbus-broker` splits policy compilation (`dbus-broker-launch`) from a capability-stripped, sandboxed routing process (`dbus-broker`) enforcing *mathematically bounded per-UID fair quotas* [359]: any caller `UID` can consume at most $m / (n + 1)$ of a target peer's currently unallocated byte, message-slot, match-rule, and `SCM_RIGHTS` FD capacity $m$ across $n$ active peer `UID`s, guaranteeing every distinct `UID` at least a $1 / n^2$ floor of bus resources even when multiple local UIDs mount a coordinated flood!

Second, D-Bus routes privileged RPCs across a *three-party triangle* (`Client` to `Bus` to `System Daemon`, followed by `System Daemon` querying `polkitd` over the bus to authorize `Client`). Passing recyclable integers (`pid_t`) or transient bus strings (`:1.92`) around that triangle produced two classic root privilege escalations [69, 341, 345]:

![Figure: Why passing numeric PIDs across asynchronous D-Bus/Polkit lookups created CVE-2021-3560, and how SO_PEERCRED paired with kernel-pinned pidfds (SO_PEERPIDFD / SCM_PIDFD) and brokerless Varlink sockets eliminate PID-reuse TOCTOU.](diagrams/11-dbus-pidfd-vs-pid-toctou.svg)

In `CVE-2013-4288` [345], D-Bus services constructed a `Polkit` `unix-process` subject `(pid, start_time)` via `polkit_unix_process_new()` (or invoked the `pkcheck --process <pid>` CLI helper) *without* supplying the caller's `connect()`-time `UID`. To learn who owned `pid`, `polkitd` later opened `/proc/<pid>/status` and read its UID! Because `start_time` inside `/proc/<pid>/stat` persists unchanged across `execve(2)`, an unprivileged local attacker (`UID 1000`) fired an asynchronous D-Bus call and immediately called `execve("/usr/bin/su", ...)` (or `pkexec`): when `polkitd` inspected `/proc/<pid>` milliseconds later, the process's file/status ownership reflected `UID 0`, tricking `polkitd` into authorizing the unprivileged request as `root` [333, 345]!

Eight years later, Kevin Backhouse (GitHub Security Lab) uncovered `CVE-2021-3560` [341] inside `polkit` (`0.113` with distro backports through `0.118`), achieving unauthenticated local root on `RHEL 8`, `Fedora`, and `Ubuntu` in under a second with zero setuid binaries and zero PID wraparound:

![Figure: Nine-step IPC sequence of CVE-2021-3560 across dbus-send, dbus-daemon, AccountsService, and polkitd, showing how killing the client ~5 ms into org.freedesktop.Accounts.CreateUser caused GetConnectionUnixUser to return NameHasNoOwner while leaving *out_uid = 0 (root).](diagrams/11-extra-cve-2021-3560-dbus-race.svg)

Walk through all nine steps of `CVE-2021-3560` [341]. An unprivileged user (`UID 1000`) invokes `dbus-send --system --dest=org.freedesktop.Accounts ... org.freedesktop.Accounts.CreateUser string:secadmin ... int32:1` (requesting creation of a `wheel`/`sudo` administrator user) and sends `SIGKILL` to `dbus-send` roughly `5 ms` later, timed to land *after* `dbus-daemon` delivers the message from unique connection `:1.92` to `AccountsService`, yet *before* `polkitd` asks `dbus-daemon` who owns `:1.92`! Inside `polkitd`, `polkit_system_bus_name_get_creds_sync()` initializes `uid_t uid = 0;` on the stack and calls `GetConnectionUnixUser(":1.92")`. Because `:1.92` has already disconnected, `dbus-daemon` replies with `org.freedesktop.DBus.Error.NameHasNoOwner`. A defective error path in `polkit_system_bus_name_get_creds_sync()` caught the D-Bus error internally yet *returned `TRUE` (success!) while leaving `*out_uid = 0` untouched* [341]! Seeing `uid == 0`, `polkitd` bypassed password authentication (`root` is unconditionally authorized!), returning `Authorized` to `AccountsService`, which created the new `sudo` administrator account and accepted an attacker-chosen password hash via `SetPassword` on the exact same race!

Modern Linux (`6.5+`), `dbus-broker`, `Polkit`, and `systemd` close IPC identity races permanently through two structural upgrades [69, 344, 346, 358, 360]:
First, Linux `6.5` (commit `7b1ecc6279be` by Christian Brauner and Luca Boccassi [358]) added `SO_PEERPIDFD` and `SCM_PIDFD` [69, 346, 357]. Rather than passing a recyclable `pid_t` or transient `:1.92` string, the socket acceptor extracts an unforgeable kernel file descriptor (`pidfd`) referencing the exact `struct pid` that initiated `connect()`, forwarding that `pidfd` via `SCM_RIGHTS` inside `Polkit` `unix-process` subjects [333]. Even if the client `SIGKILL`s itself a nanosecond later and four million processes wrap around to the identical numeric PID, the `pidfd` stays pinned exclusively to the dead original task, returning `-ESRCH` cleanly instead of ever aliasing a newcomer or defaulting to `UID 0` [69, 346]! Remember, however, that race-free caller identity still requires strict parameter validation inside the receiving daemon: when `Polkit` policies grant `allow_active=yes` to local desktop seats, spoofing physical seat variables (`pam_systemd` `XDG_SEAT` `CVE-2019-3842` [361]) or passing unvalidated script paths to root D-Bus methods (`tuned` `instance_create` `CVE-2024-52336` [362] and Snyk's Ubuntu D-Bus service chains [363]) still yields instant root execution!

Second, `systemd` (`v257` through `v259` [344, 360]) systematically replaces central D-Bus brokerage on security-critical control planes with `Varlink` (`sd-varlink(3)` and `varlinkctl(1)` [70, 344]). By `systemd v257`, `systemd` already shipped 19 `Varlink` interfaces versus 11 D-Bus services, expanding across `v258` and `v259` to drive `PID 1` service execution queries/reloads, `run0`, `systemd-creds`, `systemd-machined`, `systemd-resolved`, `systemd-repart`, `pcrextend`, and `userdb` [344, 360]. Because `Varlink` is *brokerless* and point-to-point (speaking newline-delimited JSON RPC directly over per-service `AF_UNIX` sockets such as `/run/systemd/io.systemd.Credentials`), the target daemon queries `SO_PEERCRED`, `SO_PEERSEC`, and `SO_PEERPIDFD` directly on its own accepted client socket in one hop, removing the central message-bus daemon, XML policy engine, and `:1.92` disconnect race window from the TCB altogether [70, 344, 360]!

## Distro, Immutable-OS, & Cloud Trade-Offs

Across production Linux distributions, service sandboxing and IPC mediation diverge sharply between out-of-the-box package defaults and achievable hardening ceilings [45, 68, 356, 359]. On `Fedora` and `RHEL 9/10`, core system units (`systemd-resolved`, `systemd-timesyncd`, `systemd-oomd`, `chronyd`) typically score below `2.5 OK` on `systemd-analyze security`, backed simultaneously by `dbus-broker` per-UID fair quota accounting [359] and `SELinux` `targeted` Type Enforcement (`dbus-broker` queries `SO_PEERSEC` and enforces userspace `libselinux` Access Vector Cache `send_msg` permissions before forwarding sensitive D-Bus calls!). On `Ubuntu 24.04 LTS` and `Debian 12/13`, upstream `systemd` daemons carry identical unit confinement, whereas `dbus-daemon` remains widespread and third-party `.deb` server packages (`redis-server`, `postgresql`, `nginx`, custom observability agents) frequently ship permissive `[Service]` units scoring `7.5 EXPOSED` to `9.6 UNSAFE` to preserve compatibility with legacy `/etc` scripts and arbitrary plugin paths [68, 356].

Platform engineers can close that third-party gap non-destructively using `systemd` drop-in overrides (`/etc/systemd/system/<unit>.service.d/10-hardening.conf` or `/run/systemd/system.control/`) that layer `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateDevices=yes`, `NoNewPrivileges=yes`, `RestrictSUIDSGID=yes`, `LockPersonality=yes`, `SystemCallArchitectures=native`, and `SystemCallFilter=@system-service ~@privileged` atop vendor packages while surviving `apt` and `dnf` upgrades cleanly [68, 356]. On declarative distributions such as `NixOS`, upstream module maintainers encode `serviceConfig` sandboxing directly alongside package definitions so build-time evaluation catches path mismatches early.

Immutable host operating systems (`Fedora CoreOS`, `Flatcar Container Linux`, `SUSE Linux Micro`) reinforce per-unit `ProtectSystem=strict` globally by mounting `/usr` read-only atop `composefs` or `dm-verity` ([Chapter 3](03-luks2-verity.md)), guaranteeing that even an unhardened root daemon cannot alter system binaries [46]. At the cloud-native minimalist extreme, `Talos Linux` [45] omits `systemd`, `dbus-daemon`, `dbus-broker`, and `polkitd` from Kubernetes worker nodes completely: a single static `machined` `PID 1` supervises `containerd` and `kubelet` directly and exposes node administration exclusively over mutual-TLS authenticated, RBAC-governed gRPC APIs, reducing the local multi-user IPC attack surface on worker nodes to zero.

## Seam Failures, CVEs, & Structural Bounds

Service sandboxing and local IPC mediation fail whenever unit drop-ins omit architecture pins on `seccomp`, `PID 1` or D-Bus daemons trust unsanitized caller paths and environment strings, or authorization brokers identify peers via recyclable numeric PIDs and ephemeral bus names instead of `SO_PEERCRED` and `SO_PEERPIDFD`.

| Incident / CVE | Year | Subsystem | Broken Assumption | Exploit Mechanism | Architectural Fix |
|---|---|---|---|---|---|
| `Polkit` `pkcheck` PID-Reuse Race (`CVE-2013-4288`) | 2013 | `polkitd` `unix-process` subject | `(pid, start_time)` uniquely binds caller `UID` across `/proc` reads | Client sends D-Bus call then `execve()`s setuid binary so lazy `/proc/<pid>/status` check reads `UID 0` | Pass explicit caller `uid` from `SO_PEERCRED` and migrate to `SO_PEERPIDFD` [333, 345, 358] |
| 32-Bit `int 0x80` `seccomp` Bypass | 2015-2023 | `SystemCallFilter=` without `SystemCallArchitectures=native` | Filtering `x86_64` `__NR_*` numbers blocks equivalent 32-bit syscalls | Compromised 64-bit daemon invokes `int $0x80` (`IA32_EMULATION`) where syscall numbers map to unrelated Ring 0 functions | Always pair `SystemCallFilter=` with `SystemCallArchitectures=native` [68, 104, 354] |
| `DynamicUser=yes` State-Dir Symlink Traps (`CVE-2018-15688` / `15686` era) | 2018 | `systemd` `StateDirectory=` setup | Compromised dynamic service cannot redirect `PID 1` `chown` on restart | Service plants symlink inside writable state dir followed by `PID 1` as `UID 0` during next activation | Confine under `0700` `/var/lib/private/`, walk via `O_NOFOLLOW` / `openat2(RESOLVE_NO_SYMLINKS)`, or use `MOUNT_ATTR_IDMAP` [103, 342, 364] |
| `systemd-journald` Stack Clash (`CVE-2018-16864` / `16865`) | 2019 | `systemd-journald` native socket | Unbounded `alloca()` in logging daemon stays inside stack guard | Megabyte `argv` or journal payloads jump stack guard page into heap for `journald` code execution | Replace unbounded `alloca()` with bounded heap buffers and compile with `-fstack-clash-protection` [348] |
| `pam_systemd` `XDG_SEAT` Spoofing (`CVE-2019-3842`) | 2019 | `pam_systemd` + `Polkit` `allow_active` | Caller environment cannot forge physical console seat presence | Caller injects `XDG_SEAT=seat0` into PAM env so `systemd-logind` marks session physically active (`allow_active=yes`) | Scrub untrusted `XDG_*` variables in `pam_systemd` before registering `logind` session [361] |
| `Polkit` D-Bus Disconnect Race (`CVE-2021-3560`) | 2021 | `polkitd` `GetConnectionUnixUser` | Disconnected bus client (`NameHasNoOwner`) aborts UID check | `SIGKILL` ~5 ms into `AccountsService.CreateUser` leaves uninitialized `*out_uid = 0` while returning `TRUE` | Propagate `GError` strictly, pin peer via `SO_PEERPIDFD` / `SCM_PIDFD`, or use brokerless `Varlink` [341, 344, 358] |
| `PID 1` Mount Path Stack Exhaustion (`CVE-2021-33910`) | 2021 | `systemd` `unit_name_path_escape()` | Unprivileged mount paths in `/proc/self/mountinfo` fit on `8 MiB` stack | `> 8 MiB` nested FUSE mount path triggers `strdupa()`/`alloca()` stack overflow in `PID 1`, panicking kernel | Eliminate `strdupa()` in `unit_name_path_escape()` in favor of bounded heap allocation [347, 351] |
| Unconfined `cups-browsed` UDP RCE (`CVE-2024-47176` chain) | 2024 | `CUPS` UDP `631` + `PPD` filter | Legacy print discovery daemon needs ambient network and writable exec access | Spoofed UDP `631` packet triggers outbound IPP fetch and arbitrary `FoomaticRIPCommandLine` execution | Disable unused `cups-browsed` and confine print units with `ProtectSystem=strict` + `DynamicUser=yes` [68, 343] |
| `tuned` `instance_create` Polkit LPE (`CVE-2024-52336`) | 2024 | `tuned` D-Bus daemon | `allow_active=yes` Polkit gate makes client D-Bus string parameters trustworthy | Active local user passes `script_pre=/path/to/payload` to root `tuned` D-Bus method, executing payload as `UID 0` | Require `auth_admin_keep` for privileged D-Bus mutations and reject arbitrary caller file paths [362, 363] |

Two structural bounds govern `systemd` service sandboxing and IPC mediation even when every CVE above is patched [68, 356]. First, `systemd.exec(5)` isolates *processes above a shared host Linux kernel*: if `SystemCallFilter=@system-service` leaves ~200 core POSIX syscalls (`futex`, `epoll_ctl`, `mmap`, `sendmsg`) open, a Ring 0 zero-day inside one of those allowed syscalls still escapes the unit sandbox unless hardware virtualization ([Chapter 15](15-gvisor-microvms.md)) intervenes. Second, even a `1.1 SAFE` `DynamicUser=yes` service whose UID did not exist five milliseconds ago still confronts a critical operational question: *how does it read its TLS private key, WireGuard secret, or database password at startup without leaving `0600` plaintext files sitting in `/etc` backups or exposing `Environment=` strings across `/proc` and swap?* Solving local secret custody with Linux Kernel Keyrings, `systemd-creds` hybrid `host+tpm2` sealing, and non-exportable `TPM 2.0` `PKCS#11` and OpenSSL 3 providers is the task of [Chapter 12](12-keyrings-systemd-creds.md).

## Inspecting on a Live Linux Host

Score the sandboxing posture of all active `systemd` services on the host (`SAFE`, `OK`, `MEDIUM`, `EXPOSED`, `UNSAFE`) and drill into the per-directive exposure breakdown of `systemd-resolved`:

```bash
systemd-analyze security --no-pager 2>/dev/null | head -n 18
systemd-analyze security systemd-resolved.service --no-pager 2>/dev/null | head -n 20
```

Expand the exact Ring 0 system calls permitted or denied by `systemd`'s `@system-service` and `@privileged` `seccomp-BPF` filter sets on the local CPU architecture:

```bash
systemd-analyze syscall-filter @system-service --no-pager 2>/dev/null | head -n 18
systemd-analyze syscall-filter @privileged --no-pager 2>/dev/null | head -n 15
```

Inspect active `D-Bus` system-bus services (under `dbus-broker` or `dbus-daemon`) alongside owning `PID`s, `UID`s, and `SELinux` or `AppArmor` security labels:

```bash
systemctl status dbus-broker.service dbus.service --no-pager 2>/dev/null | head -n 12 || true
busctl list --no-pager 2>/dev/null | grep -v "^:" | head -n 18
```

Enumerate brokerless `Varlink` `AF_UNIX` endpoints managed by `systemd` (`run0`, `userdb`, `creds`, `machined`) and introspect an interface schema via `varlinkctl`:

```bash
ls -la /run/systemd/io.* /run/systemd/userdb/ 2>/dev/null | head -n 14
varlinkctl introspect /run/systemd/userdb/io.systemd.DynamicUser 2>/dev/null | head -n 16 || true
```
