# Open-Source Supply-Chain Subversion: XZ Utils, Sigstore, and Reproducible Builds

## Overview

* **Link in the Chain:** Finale of Volume III; confronts the ultimate upstream boundary *preceding* every hardware, firmware, bootloader, kernel, LSM, container, and Confidential Computing mechanism in [Chapter 1](01-uefi-shim-sbat.md) through [Chapter 19](19-confidential-containers.md): proving that compiled open-source binaries signed by Linux distributions correspond faithfully to reviewed source code without hidden build-time implants.
* **Core Security Invariant:** No maintainer-rolled Autotools tarball or unpinned CI action is trusted outside immutable Git commit trees; every binary artifact carries a transparency-logged `Sigstore` (`Fulcio` + `Rekor`) signature over an `in-toto` `SLSA Build Level 3` provenance attestation emitted by an isolated hermetic builder, passes independent bit-for-bit Reproducible Build verification ($\operatorname{SHA-256}(\operatorname{Build}_A(S, E)) = \operatorname{SHA-256}(\operatorname{Build}_B(S, E))$), and minimizes transitive ELF `DT_NEEDED` linkage via on-demand `dlopen()`.
* **Deployment Profile Matrix:** Legacy distribution pipelines ingested bespoke maintainer `make dist` tarballs (`*.tar.xz`) signed by static PGP keys and linked monolithic shared-library graphs; post-2024 `Debian`, `Fedora`, `Arch Linux`, `NixOS`, `Talos Linux`, and `Chainguard Wolfi` enforce Git-tag builds, `systemd` `dlopen()` decoupling, `SOURCE_DATE_EPOCH` `rebuilderd` fleets, and `SLSA` + `Sigstore` `cosign` verification.
* **Trusted Computing Base (TCB):** Multi-party-reviewed upstream Git commit trees (free of opaque binary blobs), tenant-isolated hermetic CI control planes (`SLSA` L3), deterministic bootstrap-verified compilers (`stage0` / `DDC` + `GCC`/`LLVM`/`rustc`), independent `rebuilderd` verifiers, and `TUF`-rooted `Sigstore` (`Fulcio` OIDC CA + `Rekor` `RFC 6962` Merkle log).
* **Integration Seam & Handoff:** Closes the upstream source-to-binary chasm exposed by `XZ Utils` (`CVE-2024-3094`), completing the end-to-end Linux trust chain from auditable source commit through silicon reset (`UEFI`/`UKI`/`TPM2`), Ring 0 (`Lockdown`/`KCFI`/`Rust`/`LSMs`/`eBPF`), userspace (`run0`/`systemd-creds`/`FIDO2`), and confidential cloud (`SPIFFE`/AI Sandboxes/`SEV-SNP`/`CoCo`).

## Problem Statement & Threat Model

At 08:51 PDT on Friday, March 29, 2024, Microsoft Principal Software Engineer Andres Freund posted a forensic report to the Openwall `oss-security` mailing list (`Message-ID: <20240329155126...>` [26]) that came within days of averting a global internet catastrophe. While micro-benchmarking PostgreSQL on a Debian `sid` machine, Freund investigated why `cron` and failed SSH public-key logins (`ssh nonexistant@localhost`) were consuming `0.807` seconds instead of `0.299` seconds, burning roughly `500` milliseconds of user-space CPU cycles inside `liblzma.so.5` (`xz-utils` `5.6.0` and `5.6.1`) alongside anomalous `valgrind` stack errors [26]. Tracing instruction branches with `perf record -e intel_pt//ub` uncovered `CVE-2024-3094`: a multi-year, state-caliber upstream supply-chain operation that implanted an asymmetric `Ed448`-gated pre-authentication root backdoor straight into OpenSSH `sshd` [26, 556, 557, 558].

Pause and reckon with what `CVE-2024-3094` meant for every single runtime security barrier constructed across Parts I through IV of this book. Imagine a Fedora Rawhide or Debian Testing production server engineered to perfection: silicon `Boot Guard` and `UEFI Secure Boot` with current `SBAT` revocations ([Chapter 1](01-uefi-shim-sbat.md)), an Authenticode-signed `Unified Kernel Image` measured into `TPM 2.0` `PCR[11]` under `systemd-pcrlock` ([Chapter 2](02-uki-systemd-pcrlock.md)), an immutable `dm-verity` `/usr` partition ([Chapter 3](03-luks2-verity.md)), strict `IPE` kernel execution appraisal attested by `Keylime` ([Chapter 4](04-ima-ipe-keylime.md)), `lockdown=confidentiality` ([Chapter 5](05-kernel-lockdown-modules.md)), `FineIBT` plus hardware Shadow Stacks ([Chapter 6](06-kernel-memory-rust.md)), `SELinux` `Enforcing` confining `sshd_t` ([Chapter 7](07-stacked-lsms-landlock.md)), `SUID`-free `run0` ([Chapter 10](10-suid-to-run0.md)), hardware `FIDO2` `verify-required` OpenSSH certificates ([Chapter 13](13-pam-ssh-fido2.md)), and an `AMD SEV-SNP` Confidential VM enclave attested via `VCEK` ([Chapter 18](18-confidential-vms-svsm.md))! Every single cryptographic signature, Merkle tree hash, and hardware quote on that server would have evaluated `100% VALID`, because Debian's and Fedora's own legitimate build farms compiled `xz-5.6.1.tar.gz` and signed `liblzma.so.5.6.1` with their genuine offline distribution keys, and the implant executed inside `sshd` *prior to SSH user authentication* [26, 559]!

Runtime verification proves *artifact authenticity* ("this binary on disk matches bit-for-bit what the vendor's build farm signed"); it cannot by itself prove *build provenance or source fidelity* ("what the build farm compiled came deterministically from reviewed Git source without hidden tarball macros, compromised CI runners, or trojaned compilers"). Modern supply-chain adversaries exploit three distinct upstream seams ahead of vendor signing: maintainer capture and Git-to-tarball divergence (`XZ Utils` `CVE-2024-3094` [26, 556, 559]), build-server memory injection (`SolarWinds Orion SUNBURST`, where attackers residing inside the build VM silently injected backdoor source files during MSBuild execution before official code signing [560]), and mutable CI/CD dependency tag hijacking (`CVE-2025-30066`, where attackers repointed Git tags `v1` through `v45.0.7` of `tj-actions/changed-files` to commit `0e58ed8` to dump CI runner memory secrets across thousands of repositories [561]). Completing the Linux trust chain requires closing both the runtime blast radius of shared libraries and the cryptographic gap between reviewed Git commits and distributed binaries.

## Kernel & Userspace Mechanics

### Complete Forensic Anatomy of the `XZ Utils` Backdoor (`CVE-2024-3094`)

Reconstructing all four phases of the `"Jia Tan"` (`JiaT75`) operation exposes how surgically the attacker chained social engineering, GNU Autotools packaging conventions, Linux distro `systemd` patches, and `glibc` ELF dynamic-linker internals [26, 556, 557, 559, 562]:

![Figure: Four-stage forensic kill chain of the XZ Utils backdoor (CVE-2024-3094), tracing how a tarball-only m4 macro extracted an encrypted object implant from binary test files, rode transitive libsystemd linkage into sshd, and hijacked RSA_public_decrypt via glibc GNU_IFUNC for Ed448-gated pre-auth RCE.](diagrams/20-xz-backdoor-kill-chain.svg)

Phase 1 was *Maintainer Capture and Sanitizer Blindfolding (`2021`–`2024`)* [556, 558, 563]. Beginning in October 2021, the pseudonymous GitHub account `JiaT75` submitted clean patches to `xz-utils` while coordinated pressure personas (`Jigar Kumar`, `Dennis Ens`) sent months of guilt-inducing emails urging burned-out sole maintainer Lasse Collin to add a co-maintainer for the foundational compression library [556, 558]. By early 2023, `Jia Tan` held commit access, release PGP signing authority (`xz` `5.4.x+`), and the primary security contact email on `google/oss-fuzz`. Preparing the ground for an indirect-function (`IFUNC`) dynamic-linker hook that would have tripped Google's automated UndefinedBehaviorSanitizer and AddressSanitizer fuzzers, `JiaT75` opened `oss-fuzz` Pull Request `#10667` in July 2023 passing `--disable-ifunc` to fuzz builds under the pretext of sanitizer compatibility [563], and later slipped a single leading dot `.` syntax error into `CMakeLists.txt` and `configure.ac` (`prctl` / `landlock_create_ruleset` probe) to silently break `xz`'s own `Landlock` self-sandboxing in `5.6.0` and `5.6.1` [556]!

Phase 2 exploited *The Git-to-Tarball Seam (`m4/build-to-host.m4` + Binary Test Fixtures)* [26, 558, 559]. Committing C exploit code to `tukaani-project/xz.git` would have been caught immediately by human reviewers. Instead, `Jia Tan` committed two binary archive files, `tests/files/bad-3-corrupt_lzma2.xz` and `tests/files/good-large_compressed.lzma` (`commit cf44e4b7`, updated in `6e636819` [26, 559]), disguised as harmless decompression test inputs: opaque binary blobs unreadable in `git diff`! Next, when generating the official `xz-5.6.0.tar.gz` and `xz-5.6.1.tar.gz` release archives (`make dist`), `Jia Tan` exploited a forty-year-old GNU Autotools convention: release tarballs bundle pre-generated `configure` scripts and `m4/*.m4` macros absent from Git (and absent from GitHub's auto-generated "Source code" tag zip files!) [26, 559]. Comparing `m4/build-to-host.m4` inside `xz-5.6.1.tar.gz` against upstream GNU `gnulib` Savannah revealed a forged `# build-to-host.m4 serial 30` header (Savannah was at `serial 3`!) injecting an obfuscated `AC_CONFIG_COMMANDS([build-to-host], [eval $gl_config_gt | $SHELL 2>/dev/null])` hook executed at the end of `./configure` [559]:

```sh
# Environment gates inside Stage 1/2 build script (reconstructed from Freund's injected.txt)
if ! (echo "$build" | grep -Eq "^x86_64" && echo "$build" | grep -Eq "linux-gnu$"); then exit 0; fi
if test "x$GCC" != 'xyes' || test "x$CC" != 'xgcc'; then exit 0; fi
if test -f "$srcdir/debian/rules" || test "x$RPM_ARCH" = "xx86_64"; then
  # Extracts liblzma_la-crc64-fast.o from good-large_compressed.lzma & splices _get_cpuid()
fi
```

Look at the operational discipline of those environment checks [26, 559]: if a security engineer on macOS, FreeBSD, Alpine Linux (`musl`), Clang, or even an `x86_64` Ubuntu laptop ran `./configure && make` manually outside `dpkg-buildpackage` (`debian/rules`) or `rpmbuild` (`$RPM_ARCH == x86_64`), the script exited `0` silently and produced a 100% clean `liblzma.so`! Only inside official `.deb` and `.rpm` distribution build farms did the script run `sed rpath` + `tr "\t \-_" " \t_\-"` + `xz -d` over `bad-3-corrupt_lzma2.xz`, execute a strided `head -c +1024 >/dev/null && head -c +2048` slicer plus `RC4`-style stream cipher (`Awk`) over `good-large_compressed.lzma`, extract a pre-compiled x86-64 ELF relocatable object (`liblzma_la-crc64-fast.o`), modify `src/liblzma/Makefile`, and redirect `crc32_resolve()` and `crc64_resolve()` in `crc64_fast.c` through an injected `_get_cpuid()` entry point [26, 559, 562]!

Phase 3 and Phase 4 executed *Transitive `libsystemd` Injection, `glibc` `GNU_IFUNC` `link_map` Hooking, and `Ed448` Pre-Auth RCE* [26, 87, 557, 562, 564]:

![Figure: In-memory dynamic-linker control flow of XZ Utils (CVE-2024-3094) Stage 4 inside /usr/sbin/sshd: exploiting the early -Wl,-z,now relocation window via GNU_IFUNC before PT_GNU_RELRO freezes the GOT, walking ld.so link_map structures, and hooking RSA_public_decrypt for ChaCha20 + Ed448 pre-auth RCE.](diagrams/20-extra-ifunc-linkmap-rsa-hook.svg)

First, why was `liblzma.so.5` mapped into OpenSSH `sshd` at all when upstream portable OpenSSH never links `liblzma`? Because Debian, Ubuntu, Fedora, and RHEL applied a downstream convenience patch linking `sshd` against `libsystemd.so.0` so `sshd` could send a `READY=1` readiness datagram (`sd_notify()`) to `systemd` `PID 1`; and `libsystemd.so.0` (which also houses `sd-journal` decompression helpers!) carried hard ELF `DT_NEEDED` dynamic-library entries pulling `liblzma.so.5`, `libzstd.so.1`, `liblz4.so.1`, and `libgcrypt.so.20` into the address space of `sshd` at startup [26, 87]!

Second, look at how `Jia Tan` turned `sshd`'s own binary-hardening flags (`-Wl,-z,relro,-z,now`, Full `RELRO`!) *into an exploit enabler* via `glibc`'s `STT_GNU_IFUNC` (*GNU Indirect Function* [564]) mechanism [26, 562]:
Normally, `Full RELRO` (`PT_GNU_RELRO` + `DT_BIND_NOW`) protects a daemon against GOT-overwrite exploits by instructing `ld.so` to resolve all dynamic symbols eagerly at process startup and then call `mprotect(..., PROT_READ)` to freeze the Global Offset Table (`.got` and `.got.plt`) read-only before `main()` begins! However, to resolve an `STT_GNU_IFUNC` symbol (designed so libraries like `glibc` and `liblzma` can pick `AVX2`/`CLMUL` vs. scalar CRC implementations based on CPU features), `ld.so` *must* execute the library's C resolver function *during* early relocation, *while `.got` is still writable* (`PROT_READ | PROT_WRITE`) [26, 564]! (Ironically, as Freund noted [26], launching `sshd` with `LD_BIND_NOT=1` broke the backdoor because `sshd` relied on `-z,now` eager resolution!)

When `ld.so` invoked `crc32_resolve()` (which incremented a static counter) followed by `crc64_resolve()` calling `_get_cpuid()`, the implant contained *zero* plaintext ASCII strings (`strings liblzma.so.5.6.1` showed nothing suspicious!), matching symbol and environment names instead through a compact finite-state bit-trie lookup table [562]. It verified five stealth preconditions before lifting a finger: `argv[0]` equaled `"/usr/sbin/sshd"`, `LANG` was set, and `TERM`, `LD_DEBUG`, `LD_PROFILE`, and `rr`/`gdb` tracer artifacts were absent [26, 562]. When all preconditions held inside a real `systemd`-launched `sshd` daemon, the implant parsed `ld.so`'s internal `_r_debug` `struct link_map` doubly linked list and `_rtld_global_ro`, transiently incremented `_rtld_global_ro._dl_naudit`, and registered a synthetic audit callback on `_dl_audit_symbind_alt` [26, 562]! As `ld.so` finished binding `sshd`'s remaining symbols, the audit hook waited for `RSA_public_decrypt` (and `EVP_PKEY_set1_RSA` / `RSA_get0_key` in OpenSSL `libcrypto.so.3`), redirected `sshd`'s `.got.plt` pointer to the implant inside `liblzma`, uninstalled the audit hook cleanly (`_dl_naudit = 0`), and returned control to `ld.so`, which immediately `mprotect()`ed the hijacked GOT pointer *read-only* under `PT_GNU_RELRO` before entering `sshd`'s `main()` [26, 562, 564]!

Third, reverse engineering of the cryptographic payload (`Valsorda`, `smx-smx`, and `blasty` [557, 562]) revealed an asymmetric trigger impervious to network replay or honeypot capture. Whenever a remote TCP port `22` client sent an unauthenticated `SSH_MSG_USERAUTH_REQUEST` offering an RSA public key or SSH certificate, `sshd` called `RSA_public_decrypt` over the client's RSA modulus $N$. The implant unpacked the leading 16 bytes of $N$ as three integers $(a, b, c)$ (`uint32_t a, b; uint64_t c`) and tested $a \cdot b + c \le 3$ [557, 562]. For 99.9999999% of normal SSH keys, that check failed in nanoseconds and passed straight through to OpenSSL's real `RSA_public_decrypt`. When matched, the implant derived a `ChaCha20` key via `SHA-256` over a hardcoded 57-byte `Ed448` (`RFC 8032`) public key (`0a 31 fd 3b 2f 1f c6 92 ...`), decrypted the remaining ~`240+` bytes of $N$, verified an `Ed448` digital signature binding both the command payload and the victim server's own SSH host key SHA-256 digest, and passed the authenticated command buffer straight to `system()` as unsandboxed `UID 0` (prior to `sshd` privilege separation or PAM/audit logging!) [557, 562]! Without `Jia Tan`'s offline 448-bit `Ed448` private key, nobody on earth could synthesize a valid trigger packet.

### Architectural Remediations: `systemd` `dlopen()`, Reproducible Builds, `SLSA`, and `Sigstore`

The open-source ecosystem responded to `CVE-2024-3094` with structural engineering across four distinct layers of the software supply chain [77, 87, 565, 566, 567, 568, 569]:

Layer 1 (*Severing Transitive Shared-Library Graphs*): within weeks, OpenSSH `9.8` split `sshd` into a tiny listener binary and a separate `sshd-session` binary (re-randomized by ASLR on every connection!) and implemented `systemd`'s `NOTIFY_SOCKET` (`READY=1`) protocol directly in ~30 lines of standalone C, dropping all downstream distro patches linking `sshd` to `libsystemd.so.0` [77]! Simultaneously, `systemd` maintainers merged `PR #32024` (`systemd v256+` [87]), refactoring `libsystemd.so.0` to remove hard ELF `DT_NEEDED` dynamic links to `liblzma`, `libzstd`, `liblz4`, `libgcrypt`, `libkmod`, and `libacl`, replacing them with lazy on-demand `dlopen()` symbol tables (`src/basic/dlfcn-util.c`) invoked *only* when a program explicitly decompresses a journal archive! Today, linking `libsystemd` maps zero compression libraries into daemon memory.

![Figure: Closing the upstream open-source supply-chain gap: building strictly from signed Git commit trees (no bespoke Autotools tarballs), emitting isolated hermetic SLSA Build Level 3 provenance, verifying bit-for-bit Reproducible Builds across independent builders, and logging keyless OIDC signatures in Sigstore Rekor.](diagrams/20-slsa-sigstore-reproducible-pipeline.svg)

Layer 2 (*Abolishing Maintainer Tarballs and Enforcing Bit-for-Bit Reproducible Builds* [559, 565, 566]): Debian, Fedora, Arch Linux, NixOS, and Chainguard Wolfi moved aggressively away from ingesting maintainer-generated `make dist` Autotools tarballs, building packages instead directly from immutable upstream Git commit hashes and running `autoreconf -fi` inside clean, network-isolated distribution build sandboxes using the distribution's own audited `autoconf`/`automake`/`gnulib` macros (`m4/build-to-host.m4` `serial 30` dies on arrival when tarballs are never imported!) [559, 566]. Paired with Git-direct builds, *Reproducible Builds* (`SOURCE_DATE_EPOCH` v1.1 [565] and `rebuilderd` [566]) enforce a mathematical determinism invariant across independent builders $A$ and $B$ over Git commit tree $S$ and pinned toolchain manifest $E$:

$$\operatorname{SHA-256}\!\left(\operatorname{Build}_A(S, E)\right) = \operatorname{SHA-256}\!\left(\operatorname{Build}_B(S, E)\right)$$

By clamping embedded compiler, `ar`, `tar`, and ELF/PE timestamps to `SOURCE_DATE_EPOCH` [565], erasing host build paths via `-ffile-prefix-map=$PWD=.` and Rust `--remap-path-prefix`, fixing locale sort order (`LC_ALL=C`), and running independent multi-organization `rebuilderd` verification nodes (`96%+` across Debian `amd64` and Arch Linux [566]), both `SUNBURST`-style build-farm compromises [560] and `XZ`-style distro-conditional build implants immediately trigger public hash-mismatch alarms before packages ever reach production mirrors!

Layer 3 (*`SLSA` Build & Source Tracks + `Sigstore` Keyless Transparency* [12, 567, 568, 569, 570, 571, 572, 573]): how do downstream `bootc` OS updaters, Kubernetes admission controllers, and `Confidential Containers` `image-rs` enclaves ([Chapter 19](19-confidential-containers.md)) verify artifact provenance cryptographically before execution? Static maintainer PGP keys failed in `XZ Utils` because `Jia Tan` *held* the legitimate PGP release key [556]! OpenSSF's `SLSA` (*Supply-Chain Levels for Software Artifacts*, `v1.0` through `v1.2` [567]) replaces implicit maintainer trust with machine-verifiable `in-toto` v1.0 Attestations (`slsa.dev/provenance/v1` [567, 570]):
Under `SLSA Build Level 3` [567], builds execute inside ephemeral, isolated, hermetic build environments (such as GitHub Actions reusable SLSA builders, Tekton Chains, or Google Cloud Build) where provenance metadata is generated and signed by the *hardened build-platform control plane outside the tenant's build container* (so a malicious `Makefile` cannot forge its own provenance!), recording the exact 40-hex `gitCommit` digest, build workflow `.yml` SHA-256, and output binary SHA-256 (`SLSA v1.2` adds an explicit *Source Track* enforcing multi-party branch-protection review attestations plus *Verification Summary Attestations* `VSA` [567]).

To sign artifacts and `SLSA` attestations without long-lived stealable signing keys, `Sigstore` (`Fulcio` + `Rekor` + `cosign` [12, 568, 569, 572], whose root trust metadata is distributed resiliently via `The Update Framework` `TUF` [573]) executes a four-step keyless transparency flow: (1) the ephemeral CI builder generates a single-use ECDSA P-256 keypair in RAM and presents its short-lived OIDC JWT (`Chapter 16`) to the `Fulcio` Certificate Authority [568]; (2) `Fulcio` verifies the OIDC token and issues a short-lived X.509 code-signing certificate valid for just `10` minutes, embedding the exact OIDC issuer and GitHub/GitLab workflow URI + commit SHA inside X.509v3 SAN/OID extensions [12, 568]; (3) `cosign` signs the artifact/provenance, immediately discards the ephemeral private key from RAM, and records the signature and certificate inside `Rekor` [569], an immutable, globally audited `RFC 6962` Merkle Hash Tree transparency log [571] returning a signed inclusion proof (`Signed Entry Timestamp`); and (4) verifiers check both the `Rekor` Merkle inclusion proof and exact OIDC certificate identity (`--certificate-identity` + `--certificate-oidc-issuer`), making silent, single-target backdoor signing mathematically impossible without leaving an indelible public audit record in `Rekor` [12, 569, 572]!

## Distro, Immutable-OS, & Cloud Trade-Offs

Across the Linux ecosystem, distribution and container supply-chain architectures now separate cleanly across three maturity generations:

| Supply-Chain Generation | Source-to-Build Input | Transitive Linkage Posture | Provenance & Reproducibility | Representative Ecosystems |
|---|---|---|---|---|
| Legacy Tarball + PGP Pipeline | Maintainer `make dist` tarballs (`*.tar.xz` with pre-built `m4`/`configure`) [559] | Monolithic `DT_NEEDED` shared libs (`sshd` linked `libsystemd` + `liblzma`) [26] | Single-maintainer static PGP `.asc` signature; no transparency log | Pre-2024 traditional distro packaging |
| Git-Direct + `rebuilderd` Distro | Immutable Git commit tags + clean in-chroot `autoreconf -fi` [559, 566] | `OpenSSH 9.8` standalone notify + `systemd v256+` lazy `dlopen()` [77, 87] | `SOURCE_DATE_EPOCH` deterministic builds audited by independent `rebuilderd` nodes [565, 566] | Post-2024 `Debian`, `Arch Linux`, `Fedora`, `NixOS` |
| Hermetic `SLSA L3` + `Sigstore` OS | Multi-party-reviewed Git commit + SHA-pinned hermetic build spec [561, 567] | Minimal distroless / `dlopen()`-decoupled + memory-safe Rust core utils [33, 45] | Signed `in-toto` `SLSA` provenance + keyless `Fulcio` cert + `Rekor` Merkle log [12, 569, 570] | `Chainguard Wolfi`, `Talos Linux`, `Bottlerocket`, `Fedora bootc` [45, 572] |

Even at Generation 3, human governance and language safety remain essential complements to cryptographic provenance: remember that `bad-3-corrupt_lzma2.xz` *was* committed to Git [26, 559]! Hardened upstream projects therefore forbid unreviewed binary test fixtures inside source repositories (generating malformed fuzz inputs programmatically at test time from readable text seeds), require two-person maintainer review (`SLSA Source Track` [567]), and progressively migrate foundational compression and privilege parsers from C (`STT_GNU_IFUNC` + raw pointer arithmetic) to `#![forbid(unsafe_code)]` Rust crates (`lzma-rs`, `zlib-rs`, `sudo-rs`, `rustls` [33]).

### Closing Synthesis: The Complete Linux Trust Chain

## Inspecting on a Live Linux Host

Verify on a live Linux host that OpenSSH `sshd` (`9.8+` or post-`CVE-2024-3094` distro builds) no longer maps `liblzma.so.5` via transitive `DT_NEEDED` linkage:

```bash
ldd /usr/sbin/sshd 2>/dev/null | grep -E "liblzma|libsystemd" || echo "Clean: sshd carries zero DT_NEEDED link to liblzma"
```

```bash
readelf -d /usr/lib*/libsystemd.so.0 /lib/*-linux-gnu/libsystemd.so.0 2>/dev/null | grep "(NEEDED)" || true
```

