# About This Book

## The Author

Parag Mali is a security engineer and technical author specializing in operating-system internals, hardware-rooted platform integrity, cloud-native workload isolation, and software supply-chain security. Across *The Platform Trust Chain Series*, his work examines how modern computing platforms construct end-to-end chains of cryptographic and architectural trust from silicon reset vectors through firmware, hypervisors, kernels, local credential vaults, enterprise identity fabrics, and confidential cloud enclaves, and why real-world intrusions systematically exploit the unverified integration seams between layers.

## Method and Editorial Standard

*The Linux Trust Chain* (Volume III of *The Platform Trust Chain Series*) was written from primary technical specifications, mainline Linux kernel source code (`torvalds/linux` `6.x` trees across `security/`, `kernel/bpf/`, `mm/`, `fs/verity/`, `drivers/md/`, `rust/`, and `arch/x86/coco/`), UAPI Group specifications (`Unified Kernel Image`, `Linux TPM PCR Registry`, and `Discoverable Partitions`), `systemd` architecture documentation (`v250` through `v259`), `TCG` `TPM 2.0` and `UEFI` Forum standards, `IETF` RFCs (`RFC 9106`, `RFC 9334`), CNCF project architectures (`Keylime`, `Tetragon`, `Falco`, `SPIFFE`/`SPIRE`, `Kata Containers`, `Confidential Containers`, `Trustee`, `Sigstore`, `in-toto`), and peer-reviewed offensive/defensive security disclosures (`Openwall` `oss-security`, `Google Project Zero` / `kCTF`, `Qualys TRU`, `MSRC`, `Eclypsium`, `Binarly`, and academic proceedings) [1, 8, 9, 11, 26, 32, 76, 111].

Every chapter in this volume adheres to a strict verification discipline enforced mechanically on every build by the repository's automated audit pipeline (`tools/audit_book.py`). Architectural claims distinguish local cryptographic validity from system-level authorization; vulnerabilities are analyzed strictly as structural seam failures mapped to permanent architectural fixes rather than exploit tutorials; live host inspection commands under each chapter's closing section are bounded, read-only queries executable on standard Linux systems; all forty-three vector schematics are generated programmatically via `tools/diagram_lib.py` under seven-way geometric collision, orthogonality, and clearance verification; and every inline citation resolves without orphans against the sequential primary bibliography in [References](70-references.md). Readers who spot a technical inaccuracy, kernel ABI evolution, or broken reference link are warmly encouraged to open an issue in the series repository on GitHub.
